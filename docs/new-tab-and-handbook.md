# Native new tab, introduction, and handbook

The active tab has an explicit engine-neutral kind: `newTab` or `webpage`. A new tab still owns a WebKit session, but its web view is not loaded or displayed until navigation begins. The new-tab surface is SwiftUI, so opening it makes no request to Google and adds no web history entry. Its centered search field has no visible container, border, fill, shadow, icon, or placeholder; typed text and the caret sit directly on the page above a small Paper label. The invisible field keeps a wide click target and uses `NavigationInput` through `BrowserController`. Google remains the default search provider and can be changed in Settings. URL-only snapshots now also save explicit tab kinds; older snapshots derive them from their URLs when decoded.

The native new-tab background uses AppKit's behind-window `underWindowBackground` material with a Paper-color tint. Settings → Appearance has three local 0–100% sliders. **Tint** controls the strength of Paper's semantic background color; **Blur** controls how much of the native material appears, and 0% Blur leaves the window completely clear. The existing **New tab transparency** slider links them, setting Tint and Blur to the same percentage; after independent edits it displays their average. Existing single-slider preferences initialize both values, with 30% as the default. Changes apply to open new tabs immediately. The tint is capped below full opacity so native blur remains visible even at 100% Tint. The window and native titlebar use a clear background for new tabs and restore opaque backing for webpages. With macOS Reduce Transparency enabled, the page and window become solid Paper regardless of slider values. The borderless search input is unchanged. The effect has no animation or per-frame application code.

First launch presents a small optional three-step introduction. Step 1 recognizes ⌘L and lets the user continue after seeing the command palette. Step 2 accepts a practice search or URL locally without loading a site. Step 3 demonstrates ⌘T, Control-Tab, and ⌘W through buttons or shortcuts. Skip and completion share a local UserDefaults flag. The handbook's Replay button opens the introduction again.

The handbook is a native SwiftUI sheet with sections for getting started, search and navigation, tabs, gestures, downloads, settings, and privacy. It opens through the command palette (`Help` or `Paper Handbook`), the Help menu, or ⌘?. Phase 2B adds accurate protection, private browsing, permission, and site-data guidance, including the limits of private browsing and WebKit blocker statistics. No onboarding or handbook content makes a network request.

Verification records for Phase 1B are in [performance-benchmarks.md](performance-benchmarks.md). Isolated-bundle macOS UI tests cover new-tab focus and URL submission, ⌘T/⌘W, ⌘L, ⌘?, the overview shortcut, overview search and dismissal, Help-menu access, onboarding Skip, guided practice, and handbook Replay. Physical trackpad, VoiceOver, and end-to-end download checks remain. See [known-limitations.md](known-limitations.md).
